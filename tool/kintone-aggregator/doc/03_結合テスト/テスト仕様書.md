# テスト仕様書

## 1. 概要

本ツールの画面を操作して、画面ごとの動作を確認します。利用者の操作から、画面の表示、作られるファイル、kintone への投稿までを確認します。

前提は次のとおりです。

- テスト用の kintone 環境で実行します。本番のアプリには接続しません。
- テスト用のグループを用意し、kintone の接続情報を、テスト環境の値に設定しておきます。
- テスト用の業務日誌、パルスサーベイ、ユーザーマスターのアプリを用意しておきます。
- テスト用の投稿先（スペースとスレッド）を用意しておきます。
- Excel がインストールされている環境で実行します。

- テストの一覧

| 通番 | 画面 | ケース数 |
|---|---|---|
| 1 | 実行（一括実行） | 7 |
| 2 | 実行（アプリデータ作成） | 7 |
| 3 | 実行（アプリデータ集計） | 3 |
| 4 | 実行（アラート集計） | 3 |
| 5 | 実行（投稿） | 3 |

## 3. 注意事項

- 2.3、2.4、2.5 は、番号順に実行するため、先に実行したアプリデータ作成（2.2）の結果を使います。シナリオ単体では作成しません。
- 失敗した処理があっても、後続の処理は実行されます（一括実行）。
- 2.1、2.2、2.3、2.4、2.5 は、テスト環境のアプリと投稿先を読み書きします。
- ログの確認では、対象のグループ（ok・ng）× 処理の数だけ、ログを準備します。
- 文言（メッセージ）は、実施して確認したあとに、確認した文言に書き換えます。
- テストコードや、テストの実行手順のスクリプトは、この文書に書きません。
- 実施結果の欄は、テストを実施したときに記入します。
