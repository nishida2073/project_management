# テストシナリオルール

対象: `doc\03_結合テスト\シナリオ\*.json`、`doc\03_結合テスト\部品座標.json`

テスト仕様書の書き方は「テスト仕様書ルール」を参照してください。

## 1. 目的

テスト仕様書の 1 ケースを、UI 自動テストで確認できる形にします。シナリオは、仕様書の入力値と操作をそのまま再現し、期待値を画面・ファイル・メッセージで確認します。

## 2. ファイルと構成

- ファイル名は `<節>-<通番>-<内容>.json` の形にします（例: `2.1-07-batch-ng-client.json`）。仕様書の通番と一致させます。
- JSON の項目は次の 5 つです。
  - `name`：確認内容（仕様書の期待値と同じ内容）。
  - `kind`：`正常系` または `異常系`（仕様書の区分と一致させます）。
  - `vars`：入力値の変数。対象のグループは `"client": "ok"`、`"client": "ng"` のように書きます。
  - `setup`：テストの前に用意するファイル（後述の準備の操作）。準備するものがなければ空の配列にします。
  - `steps`：操作と確認を、書いた順に実行します。
- 文字コードは UTF-8（BOM なし）、インデントは 2 つの空白で書きます。
- 前段の操作（別の画面の処理）は、先頭の `steps` に書きます。

## 3. 操作の書き方

- 部品は `part` で指定します。`part` は `画面/部品` の形で、`部品座標.json` の `screen` と `name` に一致させます。座標は実行時に `part` から読み込まれるので、`x` と `y` は書きません（`part` と `x` を同時に書くとエラーになります）。
- タブを選ぶ、ボタンを押すなどの操作は `clickAt` を使います。`click`（部品名で探す操作）は使いません。
- メニューのタブと、画面のタブを押すたびに、`wait` を 500ms 入れます。
- 画面の下にある欄を操作するときは、`wheelAt`（`x`、`y`、`delta`）で、欄を表示する位置までスクロールします。`x`、`y` は、スクロールする領域の中の位置を書きます。`delta` は、下へ送るときは負の値（例: `-1200`）を書きます。スクロールの後は、`wait` を 800ms 入れます（記述例：8.11）。
- 別のウィンドウ（ダイアログ以外）を閉じるときは、`closeWindow`（`title`、`keys`）を使います。`title` は、ウィンドウのタイトルの一部です。`keys` は省略すると Alt+F4 を送ります。窓が見つからないときは何もせず、エラーにもなりません。ダイアログの場合は、`pressKey` を使います（記述例：8.11）。
- 値の選択と入力は次のとおりです。
  - コンボボックスは `selectComboAt` で選びます。`value` を空にすると先頭（「すべて」など）を選びます。`value` には `{{client}}` のような変数を書けます。
  - 1 行のテキスト欄は `typeAt` で入力します（既存の値は全選択してから入力します）。
  - 日本語の値（テキスト欄、表のセルなど）は `pasteAt` で入力します。`typeAt` と `selectComboAt` は文字を送るため、日本語は入りません。
  - 日本語の選択肢は、`selectComboAt` で選べません。`keysAt`（`part`、`keys`）で、部品をクリックしてから矢印キーと Enter で選びます（例: 3 番目の項目は `{DOWN}{DOWN}{ENTER}`）。項目の順番は、画面の定義（画面設計）の順に合わせます。
  - 保存対象など、ほかのコンボの選択は、対象のグループを選んだ後で行います（対象のグループを選ぶと開いたままになる一覧があるため）。
- 複数行の欄と、表のセルへの入力は `pasteAt`（`part`、`value`）で行います。表のセルは、1 行の値でも `pasteAt` を使います。
- 仕様書の入力値に書いた「すべて」は、シナリオでも必ず選びます（空の `selectComboAt` で選びます）。仕様書の入力値と、シナリオの選択を一致させます。
- 画面の既定の値を確認するケースでは、既定の値を変えない操作は書きません。

## 4. 確認の書き方（部品ごと）

- タブ、ボタン、ラジオボタン（操作: `clickAt`）: 押した後の表示・ファイル・メッセージで確認します。ラジオボタンは、切り替えた項目のログ欄で確認します。（記述例：8.1、8.6、8.7）
- コンボボックス（操作: `selectComboAt`）: 選んだ後の表示を `expectTextAt` で、その部品の位置の文字列（`^値$`）で確認します（例: 新規作成したグループの名前）。（記述例：8.3、8.6）
- テキスト欄（操作: `typeAt`）: 入力値は、保存後のファイル（`expectFileContains`）か、再読込後の表示（`expectTextAt`）で確認します。（記述例：8.1）
- 空の欄（操作なし）: `expectTextAt` は文字のない欄を読めないため、`pattern: "."` と `absent: true` を付けて、その位置に文字がないことを確認します（例: 追加した行の名前の欄が空であること）。
- 真偽値の欄（TRUE/FALSE の選択欄、Excel の TRUE/FALSE のセル）: 画面の選択欄は `expectTextAt` で `^TRUE$`、`^FALSE$` と確認します。Excel のセルは、`excelExpect` で `equals: "True"` か `"False"` と書きます（0/1 ではありません）。
- 状態欄（操作なし）: `expectTextAt` で、状態の文字列を正規表現で確認します。保存と再読込は「完了」（`^完了$`）、実行は「成功」「警告」「失敗」「スキップ」（`^(成功|警告)$` など）です。（記述例：8.1、8.2）
- チェックボックス（操作: 変える場合のみ `clickAt`）: `expectCheckedAt` で、`checked` の真偽（`true` / `false`）を確認します。（記述例：8.2）
- ログ欄（操作なし）: `expectTextAt` を、ログ欄の位置（`tolX: 500`、`tolY: 180` を指定）で使い、ログの行（例: `download-test-results-ok`）を確認します。欄全体の文字は見ません。（記述例：8.3、8.4）
- 確認ダイアログ（操作: `pressKey`、`window` にダイアログのタイトル）: 表示された文言を `expectDialogText` で確認し、`n`（いいえ）または `y`（はい）を `pressKey` で送ります。（記述例：8.4）
- メッセージ（エラー・通知）（操作なし）: `expectMessage` で、ウィンドウのタイトルと文言を確認します。（記述例：8.5）
- 入力ダイアログ（新規作成など）（操作: `enterDialog`）: `value` を入力し、Enter で確定します。（記述例：8.6）
- キャンセル（操作: `pressKey` の `{ESC}`）: ダイアログを閉じた後、作られなかったファイル（`expectFile` の `exists: false`）を確認します。（記述例：8.6）
- 作られるファイル（操作なし）: `expectFile`（`path`、`exists`、必要なら `filter`）で確認します。Excel（`.xlsx`）も、ファイルが作られたことだけを確認します。（記述例：8.2）
- Excel の中身（操作なし）: 仕様書の期待値に、シートの中身（セルの値など）を書いた場合だけ、`excelExpect`（`path`、`sheet`、`cell`、`equals` または `notEquals`）で確認します。中身を書いていない場合は、ファイルの有無だけを確認します（記述例：8.12）。
- 設定ファイルの内容（操作なし）: `expectFileContains` で、「キー=値」を確認します。（記述例：8.1）
  - JSON の設定ファイル（例: `collect-data-defs.json`）は、「キー=値」ではなく、ファイルに書かれた形（`"キー": "値"`）で確認します。空白も、ファイルと同じに書きます（例: `"newName":  "saved-col"`）。
- 削除した設定項目（操作なし）: `expectFileNotContains` で、削除した「キー=値」が設定ファイルに残っていないことを確認します。削除は、削除ボタン（`clickAt`）で行い、保存して確認します（記述例：8.10）。
- 削除したログ（操作なし）: ログ欄で、残る・消えることを確認します。消えたことは `expectTextAt` に `absent: true` を付けて確認します（記述例：8.4）。ログのファイルは、ログ欄で確認し、設定ファイルでは確認しません。
- 表示されないこと（操作なし）: `expectTextAt` に `absent: true` を付けます。ログ欄の場合は、`tolX`、`tolY` も書きます（記述例：8.9）。
- 窓全体の文字（操作なし）: 欄の文字を読めない場合だけ、`expectEditContains`（`text`）で窓全体の文字を確認します（記述例：8.9）。
- 窓全体に文字がないこと（操作なし）: `expectEditNotContains`（`text`）で、窓の入力欄のどれにも、その文字がないことを確認します。再読込で、入力した仮の値が戻ったことを確かめるときに使います。確認は 1 秒待ってから行います（記述例：8.11）。
- ログのフォルダ（操作なし）: `expectLogFile`（`path`、`timeoutSec`）で、フォルダの有無を確認します。（記述例：8.3、8.8）
- ログの中身（操作なし）: `expectLogContains`（`path`、`filter`、`contains`）で、`path` のフォルダにある、`filter` に合うファイルの中に `contains` の文字があることを確認します。`filter` はワイルドカードで書きます（記述例：8.11）。
- 画面が開いたこと（操作なし）: `expectWindow`（`title`、`timeoutSec`）で、タイトルの一部が一致するウィンドウが開いたことを確認します。開いた後、5 秒待ってから、画面の証跡を残します（記述例：8.11）。
- 状態欄の確認の待ち時間（`timeoutSec`）は、保存・再読込が 15 秒、単独の実行が 60 秒を基本にします。実行に時間がかかる処理は、その処理に合わせて個別に長くします（一括の全処理の目安は 900 秒）。
- 表示の切り替え（ログの絞り込み）は、次の順で確認します。1. グループを「すべて」「ok」「ng」「すべて」の順に切り替える。2. 続けて、ラジオボタンや識別名などの項目を切り替え、最後に「すべて」（または先頭の項目）に戻す。3. 切り替えるたびに、表示されるものと、表示されないものを、ログ欄で確認する。

## 5. 準備（setup）

- 設定ファイルの値を読み込む（規定値の確認）: 規定値は、シナリオの `fixtureVars` で設定ファイルから読み込みます。`fixtureVars` は「変数名: 設定ファイルのキー」の形で書きます。読み込み元は、既定では `clients\<client>.bat`、共通タブの値は `fixtureFile`（`bats\common.bat`）で指定します。確認では、`{{変数名Re}}`（正規表現用の値）を `^…$` の中に書きます。具体的な値は、シナリオにも仕様書にも書きません（記述例：8.13）。
- 入力値になるファイルは、次のどちらかで用意します。
  - `doc_結合テスト	est-data` にあるファイル（`clients`、`template` など）は、テストの開始時に、すべてのシナリオへコピーされます。`setup` では作らず、仕様書の入力値のファイル名と一致することを確認します。
  - `test-data` にないファイルは、`setup` の `writeFile`（`path`、`text`、`encoding`）で作ります。
- フォルダは `makeDir`、ファイルの複製は `copyFile`（`from`、`to`）で作ります。
- テストの後に削除するファイルは `deleteFile` で作ります（`setup` に書きます）。
- ログのファイルは、仕様書の入力値に書かず、注意事項に書いた数だけ `setup` で準備します。

## 6. タブごとのシナリオ

### 6.1 一括実行タブ

- 開始は「メニュー/実行タブ」→「実行/一括実行タブ」の順に `clickAt` し、それぞれ `wait` で 500ms 待ちます。
- 処理のチェックボックスは、開始時の状態（既定の状態）を、すべての項目について `expectCheckedAt` で確認します。既定のまま実行する正常系のケースに適用します。チェックを外すケースは、外した項目を含め、すべての項目を確認します。メッセージだけを確認する異常系のケースは、この確認をしません。
- 対象のグループ（必要なら他の入力値）を `selectComboAt` で選び、「実行（一括実行）/実行」を `clickAt` します。
- 処理ごとの状態欄を `expectTextAt` で確認します（例: `^(成功|警告)$`）。全体の状態欄も同じく確認します。
- 出力ファイルは `expectFile` で確認します。
- チェックを外した処理は、その処理の状態欄が `スキップ` であることを確認します。チェックを外す操作は、`clickAt` で行います。
- 異常系で、メッセージだけを確認する場合（例: 対象日が空のとき）は、状態欄の確認は書かず、`expectMessage` だけで確認します。
- ログのフォルダの有無は、`expectLogFile`（`path`、`timeoutSec`）で確認します。期待値には書きません（一括・複数実行も同じ）。

### 6.2 複数実行タブ

- 開始は「メニュー/実行タブ」→「実行/複数実行タブ」の順に `clickAt` します。
- 処理ごとの状態欄（「実行（複数実行）/状態」など）で確認します。
- ログのフォルダの有無は `expectLogFile` で確認します。
- 異常系で、メッセージだけを確認する場合（例: 対象日が空のとき）は、状態欄の確認は書かず、`expectMessage` だけで確認します（6.1 と同じ）。

### 6.3 実行タブ

- 開始は「メニュー/実行タブ」を `clickAt` します。
- 処理ごとの画面（「実行（処理名）」の節）を選び、入力値を `selectComboAt` と `typeAt` で入力し、「実行」を `clickAt` します。
- 状態欄を `expectTextAt` で確認し、出力ファイルを `expectFile` で確認します。

### 6.4 共通タブ

- 開始は「メニュー/環境設定タブ」→「環境設定/共通タブ」の順に `clickAt` します。
- 入力する値は、保存の確認では `saved-○○`、再読込の確認では `tmp-reload` を使います。空の入力は、`typeAt` で値を空にします。設定ファイルの規定値は、`fixtureVars` で読み込んで確認します（記述例：8.13）。
- 保存のケースは、テキスト欄を `typeAt` で、その項目だけ変えた値（識別しやすい値、例: `saved-log`）にし、「保存」を `clickAt` します。
  - 状態（保存）を `expectTextAt` で `^完了$` を確認します（待ち時間 15 秒）。
  - `bats/common.bat` を `expectFileContains` で「キー=値」の形で確認します（例: `CommonLogPath=saved-log`）。
- 再読込のケースは、テキスト欄を `typeAt` で仮の値にし、「再読込」を `clickAt` します。
  - 状態（再読込）を `expectTextAt` で確認します。
  - 対象の欄を `expectTextAt` で、既定の値を文字列の完全一致（`^既定の値$`）で確認します。
- 保存のケースと再読込のケースの組は、1 つの項目につき 1 組にします。
- 保存先が設定ファイル（`bats/common.bat`、`clients/*.bat`）ではない画面（例: 環境設定（マスター））は、`expectFileContains` の代わりに、状態（保存）と、画面の表示で確認します（記述例：8.9）。

### 6.5 グループ別タブ

- 開始は「メニュー/環境設定タブ」→「環境設定/グループ別タブ」の順に `clickAt` します。
- 対象のグループを `selectComboAt`（`{{client}}`）で選びます。
- 新規作成は、「新規作成」を `clickAt` し、ダイアログに `enterDialog`（`window` はダイアログのタイトル、`value` は新しいグループ名）で入力します。確認は、対象のグループのコンボボックスを `expectTextAt` で `^グループ名$` にします。
- 新規作成のキャンセルは、「新規作成」を `clickAt` し、`pressKey`（`{ESC}`）でダイアログを閉じます。作られなかったファイル（`clients/<グループ名>.bat`）を `expectFile` で `exists: false` にします。
- コピーのケースは、「コピー」を `clickAt` し、コピー元の項目を `selectComboAt` で選んでからコピー先のグループ名を `enterDialog` で入力します。
- 保存と再読込は、共通タブと同じ形で確認します。保存先は `clients/<グループ名>.bat` です。
- 入力する値は、6.4 と同じ（保存の確認は `saved-○○`、再読込の確認は `tmp-reload`、空は `typeAt` で値を空にする）。
- 例外: 接続テスト（テスト接続、テスト投稿など）で、接続の結果を確かめるための値は、`saved-○○` にせず、テストの目的どおりの値を書きます。有効な値（例: 136）、存在しない値（例: 99999999）、ダミーのパスワード（例: wrong-password）が対象です。
- 規定値の確認は、`fixtureVars` で `clients/<client>.bat` から読み込みます（記述例：8.13）。

## 7. 注意

- 認証の値（パスワード、トークン）は、実際の値を書きません。保存の確認では、テスト用のダミー値（例: `saved-pass`）を `typeAt` で入力します。仕様書には、保存場所だけを書きます。
- 画面、部品、処理が変わったときは、`部品座標.json` とシナリオを同じタイミングで更新します。
- 画面の証跡（スクリーンショット）は、次の順で保存されます（`shot` の手順と、`clickAt`、`selectComboAt`、`pressKey`、`expectDialogText`、`enterDialog`、`expectMessage`、`expectWindow`、`click` などの後）。ファイル名は `<シナリオ名>-<連番>.png` です。
  - 完了後の画面（状態欄の結果など）を残すため、すべてのシナリオの最後に `{"action": "shot"}` を書きます。`expectTextAt` や `expectFile` の後は、自動では撮られません。
  - 最後の `shot` の前に、確認の手順（`expectTextAt` など）を置きます。確認の結果が見えている画面になります。
  - 撮影は、アプリの窓の位置を画面から切り出すため、テストの実行中は、ほかの窓（エディタなど）を前面に出しません。ほかの窓が重なると、そちらが写ります。

## 8. 記述例

現状のシナリオ（track・ka・krg・pkg）から、実際に使っている書き方を抜き出しています。

### 8.1 シナリオ全体（共通タブの保存）

対応する部品：タブ、ボタン、テキスト欄、状態欄、設定ファイルの内容

`track-aggregator\doc\03_結合テスト\シナリオ\2.7-05-common-log-path-save.json`

```json
{
  "name": "2.7-05 環境設定（共通）でログの出力先を変えて保存すると、変えた値が common.bat に保存される",
  "kind": "正常系",
  "vars": {
    "client": "ok"
  },
  "setup": [],
  "steps": [
    { "action": "clickAt", "part": "メニュー/環境設定タブ" },
    { "action": "wait", "ms": 500 },
    { "action": "clickAt", "part": "環境設定/共通タブ" },
    { "action": "wait", "ms": 500 },
    { "action": "typeAt", "part": "環境設定（共通）/ログの出力先", "value": "saved-log" },
    { "action": "clickAt", "part": "環境設定（共通）/保存" },
    { "action": "expectTextAt", "part": "環境設定（共通）/状態（保存）", "pattern": "^完了$", "timeoutSec": 15 },
    { "action": "expectFileContains", "path": "bats/common.bat", "contains": "CommonLogPath=saved-log" }
  ]
}
```

- `name` は、仕様書の期待値と同じ内容の確認です（「〜すると、〜される」の形）。
- 1 つの項目（ログの出力先）だけを変えて、保存と確認を行います。

### 8.2 一括実行（状態欄で確認）

対応する部品：チェックボックス、状態欄、作られるファイル

`track-aggregator\doc\03_結合テスト\シナリオ\2.1-01-batch-run.json`（抜粋）


### 8.3 ログ欄（絞り込みの確認）

対応する部品：コンボボックス、ログ欄、ログのフォルダ（準備）

```json
{ "action": "writeFile", "path": "logs/create-space-from-template-ok-config1_20260101_000000.log", "text": "create-space-from-template-ok-config1" },
```
