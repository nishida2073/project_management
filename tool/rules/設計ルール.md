# 設計ルール

設計文書の種類ごとに、目的、書く内容、注意点を示します。共通の書き方は「共通ルール」を参照してください。

## 0. 設計フォルダの文書一覧

設計フォルダ（`02_設計`）の文書は次の 5 種類です。現時点で書き方のルールがあるのは機能一覧とアーキテクチャ設計だけです。データ設計、画面設計、処理フローのルールは、文書を作るときに決めます。

| 文書 | ファイル | ルール |
|---|---|---|
| 機能一覧 | `機能一覧.md` | 定義済み（1 節） |
| アーキテクチャ設計 | `アーキテクチャ設計.md` | 定義済み（2 節） |
| データ設計 | （未作成） | 未定 |
| 画面設計 | （未作成） | 未定 |
| 処理フロー | （未作成） | 未定 |

## 1. 機能一覧（`機能一覧.md`）

### 目的

利用者が使える機能を一覧で示します。

### 書く内容

- 大項目は機能のまとまりごとに分けます（例: 実行、ログ、環境設定）。
- 大項目の見出しには番号を付けます（例: `## 1. 実行`）。
- 大項目の下に機能を、機能の下に機能の概要を、入れ子の箇条書きで書きます。
- 機能名は画面の表示名ではなく、機能そのものを表す名前で書きます。
- 入れ子の段階数は大項目ごとに決めます。
  - 実行: 3 段階まで（機能 → 内容 → 対象）
  - 環境設定: 4 段階まで（機能 → 内容 → 対象 → 項目）

### 書式の例

```markdown
## 1. 実行

- アプリデータの作成
  - アプリからデータを取得し、集計用データを作成する
    - 業務日誌
    - パルスサーベイ
```

### 注意

- 画面に出ない機能は書きません。
- 項目の並びは処理の流れや機能どうしの関係に沿って書きます。

## 2. アーキテクチャ設計（`アーキテクチャ設計.md`）

### 目的

システムの構成、処理の流れ、設定の層、外部との連携を示します。関数や変数の詳細は書きません。

### 章立て

章は次の順に書きます。必要のない章も、番号を詰めずに残すか、文書全体で振り直します。

| 章 | 見出し | 書く内容 |
|---|---|---|
| 1 | 概要 | 目的、処理の層（表で 3 層程度） |
| 2 | ディレクトリ構成 | フォルダ構成（ツリー）。入口となるファイルのみ名前を書く |
| 3 | 全体処理フロー | 処理の順序（ツリー）。日付とグループの扱いは 3.1、3.2 に分ける |
| 4 | 引数の規約 | 引数の形式と、親子の受け渡し |
| 5 | 設定の層 | 設定の種類と内容（表） |
| 6 | ジョブとワーカー | ジョブの責務、起動と終了判定、ワーカーごとの入出力（表） |
| 7 | 共通ライブラリ | 機能の分類（表）。ファイル名は書かない |
| 8 | 排他制御 | 排他の対象と用途（表） |
| 9 | 入出力ファイル | フォルダ、ファイルの内容（表） |
| 10 | GUI の構成 | タブ、主な操作 |
| 11 | 外部連携 | 連携先、用途、通信内容（表） |
| 12 | エラー処理と運用上の注意 | 利用者が注意すること（箇条書き） |
| 13 | 既知の制約 | 前提と制約（箇条書き） |

### 書き方の注意

- 設定の既定値の一覧は書きません。場所と役割だけを書きます。
- 処理ごとの説明は、役割と入出力（表）で書きます。
- 機密情報（パスワードなど）の保存場所は書きますが、値は書きません。
