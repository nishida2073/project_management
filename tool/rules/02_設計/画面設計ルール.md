# 画面設計ルール

対象: `doc\02_設計\画面設計.md`

共通の書き方は「共通ルール」、設計全体の書き方は「設計ルール」を参照してください。

## 1. 目的

操作画面の構成と、各画面の項目と操作を示します。

## 2. 書く内容

- 文書は次の構成で書きます。
  - `## 1. 概要`: 操作画面の構成を 1 段落で書きます。
    - `### 1.1 画面の一覧`: 画面と内容を表で書きます（画面、内容）。
    - `### 1.2 画面遷移図`: 画面の遷移を Mermaid のフローチャート（`flowchart TD`）で書きます。ツリーでは書きません。
  - `## 2. 各画面`: 画面ごとに節を分けます（`### 2.1 実行（一括実行）` のように書きます）。
- 各画面の項目は表で書きます（項目、種類、内容）。項目の順は、画面の並び（上から下、左から右）に合わせます。画面の上部にあるボタンは表の先頭に書きます。
- 同じ名前の項目が画面に複数ある場合は、名前の後ろに括弧で区別を書きます（例: `テスト接続（業務日誌）`、`テスト接続（ユーザー）`）。
- 同じ項目名の行は、種類と内容の書き方を揃えます。
- コンボボックスやラジオボタンの選択肢（候補の一覧）は書きません。
- 種類は、次のいずれかを使います: テキスト、テキストエリア、コンボボックス、チェックボックス、ラジオボタン、ボタン、リンク、表、ラベル。
- 処理ごとに枠が分かれている画面は、枠ごとに小見出し（`#### 業務日誌` のように）を付け、項目表を枠ごとに分けます。
- 各画面の操作は、表の下に箇条書きで書きます。
- 画面の名前、項目名、ボタン名は、GUI（`bats\gui.ps1`）と共通部品（`bats\library` のファイル）に書かれた表示文言から取得して書きます。推測で書いた名前は使いません。
- 「状態」「開く」など、表示文言にない説明の言葉を使う場合は、そのことを明記します。
- 画面として扱うのは、タブや画面のまとまりです。ダイアログは画面として書きません。
- 画面の表示状態、既定値、処理の動作などは、コードを確認してから書きます。確認できない内容は「（未確認）」と明記します。

## 3. 注意

- 画面の内容はプロジェクトごとに異なります。書く内容は、そのプロジェクトの画面をもとにします。
- 関数名、変数名は書きません。
