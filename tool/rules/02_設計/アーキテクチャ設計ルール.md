# アーキテクチャ設計ルール

対象: `doc\02_設計\アーキテクチャ設計.md`

共通の書き方は「共通ルール」を参照してください。

## 1. 目的

システムの構成、処理の流れ、入力と出力のデータ、外部との連携を示します。関数や変数の詳細は書きません。

## 2. 章立て

章は次の順に書きます。

| 章 | 見出し | 書く内容 |
|---|---|---|
| 1 | 概要 | 目的、処理の層（表で 3 層程度） |
| 2 | 実行環境と前提 | 必要なソフトウェア、通信、認証などの前提（表：通番、項目、内容） |
| 3 | ディレクトリ構成 | フォルダ構成（ツリー）。ファイル名は書かず、フォルダごとに置くファイルの種類を役割で書く（例: 入口のバッチ、各処理のバッチ）。説明の位置は、ほかの行と揃えます。入口のバッチの行は、「入口のバッチ」の後に空白を入れ、「bats本体の呼び出し」を各処理のバッチの行の説明と同じ位置に置きます（例: `├─ 入口のバッチ                bats本体の呼び出し`）。 |
| 4 | 処理概要 | 処理の一覧（表：通番、処理、入力、出力）。入力と出力は、データ設計で定義したデータ名を書く |
| 5 | 共通ライブラリ | 機能の分類（表）。ファイル名は書かない |
| 6 | 外部連携 | 連携先、用途、通信内容（表） |
| 7 | エラー処理 | 処理が失敗したときの表示と記録（箇条書き） |
| 8 | 運用上の注意 | 利用者や運用担当者が注意すること（箇条書き） |

## 3. 書き方の注意

- 設定の既定値の一覧は書きません。場所と役割だけを書きます。
- 処理ごとの説明は、役割と入出力（表）で書きます。
- 機密情報（パスワードなど）の保存場所は書きますが、値は書きません。
- 7 章（エラー処理）には、処理が失敗したときは、画面の状態に「失敗」と表示し、実行ログに記録すると書きます。この動作は、どのプロジェクトでも同じです。
