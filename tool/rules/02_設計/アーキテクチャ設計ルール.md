# アーキテクチャ設計ルール

対象: `doc\02_設計\アーキテクチャ設計.md`

共通の書き方は「共通ルール」を参照してください。

## 1. 目的

システムの構成、処理の流れ、入力と出力のデータ、外部との連携を示します。関数や変数の詳細は書きません。

## 2. 章立て

章は次の順に書きます。

| 章 | 見出し | 書く内容 |
|---|---|---|
| 1 | 概要 | 目的、処理の層（表で 3 層程度） |
| 2 | ディレクトリ構成 | フォルダ構成（ツリー）。ファイル名は書かず、フォルダごとに置くファイルの種類を役割で書く（例: 入口のバッチ、各処理のバッチ）。説明の位置は、ほかの行と揃えます。入口のバッチの行は、「入口のバッチ」の後に空白を入れ、「bats本体の呼び出し」を各処理のバッチの行の説明と同じ位置に置きます（例: `├─ 入口のバッチ                bats本体の呼び出し`）。 |
| 3 | 処理概要 | 処理の一覧（表：通番、処理、入力、出力）。入力と出力は、入力データと出力データのデータ名を書く |
| 4 | 入力データ | 入力データの一覧（表：通番、データ名、場所、内容） |
| 5 | 出力データ | 出力データの一覧（表：通番、データ名、場所、内容） |
| 6 | 共通ライブラリ | 機能の分類（表）。ファイル名は書かない |
| 7 | 外部連携 | 連携先、用途、通信内容（表） |
| 8 | GUI の構成 | タブ、主な操作 |
| 9 | エラー処理と運用上の注意 | 利用者が注意すること（箇条書き） |
| 10 | 既知の制約 | 前提と制約（箇条書き） |

## 3. 書き方の注意

- 設定の既定値の一覧は書きません。場所と役割だけを書きます。
- 処理ごとの説明は、役割と入出力（表）で書きます。
- 機密情報（パスワードなど）の保存場所は書きますが、値は書きません。
