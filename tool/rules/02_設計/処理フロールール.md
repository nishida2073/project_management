# 処理フロールール

対象: `doc\02_設計\処理フロー.md`

共通の書き方は「共通ルール」、設計全体の書き方は「設計ルール」を参照してください。

## 1. 目的

画面のボタンごとに、押したときに行われる処理の流れを示します。

## 2. 書く内容

- 文書は次の構成で書きます。
  - `## 1. 概要`: 文書の対象を 1 段落で書きます。
    - `- 処理の一覧`: 処理の一覧を表で書きます（画面名、ボタン名、内容）。一覧は `bats\gui.ps1` から取得し、ボタン名は GUI の表示文言をそのまま書きます。
- 処理ごとに枠（グループの見出し）があるボタンは、ボタン名の後ろに枠名を括弧で付けます（例: `実行（業務日誌）`、`テスト接続（認証情報）`）。枠がないボタンは、ボタン名だけを書きます。
  - `## 2. 各ボタンの処理フロー`: ボタンごとに節を分けます。見出しは「画面名[ボタン名]」の形で書きます（`### 2.1 実行（一括実行）[実行]` のように書きます）。
  - `## 3. 注意事項`: 業務上の不都合になる内容だけを、箇条書きで書きます。
- 処理の一覧の「画面名」「ボタン名」は、GUI の表示文言に合わせます。
- 処理の一覧の順番は、GUI の表示順（タブの順、タブ内のボタンの順）に合わせます。
- 処理の一覧には、画面のボタンをすべて載せます。ただし、ファイルやフォルダを選ぶだけの「参照」ボタンと、入力を消去するだけの「クリア」ボタンは載せません。
- 各ボタンの手順は、番号付きの一覧で書きます。1 つの手順は、1 文で「〜します。」と書きます。
- 各ボタンの手順の下に、同じ内容を示す Mermaid のフローチャート（`flowchart TD`）を付けます。フローチャートの各ノードは、手順と同じ文にします。必須の入力や中止の手順は、判定のノードで書きます。中止は、メッセージの出力と終了を別のノードにします。
- 判定のノードは、「はい」の枝を先に、「いいえ」の枝を後に書きます。図では「はい」が左に来るようにします。
- 手順で表示する状態は、GUI の表示文言（成功、警告、失敗、スキップなど）に合わせます。
- 処理の中で中止する条件は、手順の中で書きます。
- 確認していない内容は「（未確認）」と明記します。

## 3. 注意
- 関数名、変数名、引数名は書きません。
- 個別のバッチ名、スクリプト名は書きません（入口となるファイルを除く）。
- 処理の内容はプロジェクトごとに異なります。書く内容は、そのプロジェクトの画面と処理をもとにします。
- 注意事項には、処理の失敗時の動作、出力ファイルに関する注意など、利用者が知るべき基本的な動作を書きます。特定の種類のファイルや製品名に限定せず、一般的な書き方で書きます（例: 「出力先のファイルを開いたままにすると、書き込みに失敗する可能性があります。」）。

## 4. 処理ごとの記述パターン

同じ種類の処理は、次の手順の並びで書きます。

### 4.1 実行

1. 対象日と対象のグループを確認します。
2. 必須の入力がない場合は、メッセージを出力して終了します。
3. 対象の処理を実行します。
4. 処理の状態を表示します。
5. 実行ログを画面下部に出力します。

### 4.2 一括実行

1. 対象日と対象のグループを確認します。
2. 必須の入力がない場合は、メッセージを出力して終了します。
3. 選んだ処理を順に実行します。
4. 処理ごとに、状態を表示します。
5. 実行ログを画面下部に出力します。

### 4.3 保存

1. 入力された内容を確認します。
2. 入力された内容を、対象の設定ファイルまたはデータに書き込みます。
3. 画面の表示を、保存後の内容に更新します。
4. 結果を、ボタンの横に表示します。

### 4.4 再読込

1. 対象の設定ファイルまたはデータの内容を読み込みます。
2. 読み込んだ内容で、画面の入力欄または表を表示し直します。
3. 結果を、ボタンの横に表示します。

### 4.5 新規作成

1. 名前を入力する画面を表示します。
2. 入力された名前が、既存のものと重複していないかを確認します。
3. 重複していなければ、新しいものを作成し、一覧に追加します。

### 4.6 削除

1. 削除の対象を確認します。
2. 削除します。


### 4.7 追加

1. 表の末尾に、空の行を追加します。
2. 画面の表示を、追加後の内容に更新します。

### 4.8 テスト接続

1. 対象の入力（接続先の情報）を確認します。
2. kintone に接続し、接続できるかを確認します。
3. 結果を、ボタンの横に表示します。

### 4.9 テスト投稿

1. 投稿先の情報を確認します。
2. テスト用のコメントを、投稿先のスレッドに投稿します。
3. 結果を、ボタンの横に表示します。

### 4.10 同期実行

1. 対象のグループを確認します。
2. アプリIDが入力されていない場合は、メッセージを出力して終了します。
3. 同期元の内容を、同期先に書き込みます。
4. 結果を、ボタンの横に表示します。
