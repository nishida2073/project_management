# ファイル仕様書ルール

対象: 本ツールが読み書きするファイル（JSON、Excel など）の仕様書

共通の書き方は「共通ルール」を参照してください。

## 1. 目的

ファイルの形式を、読む人と作る人が同じ理解で使えるようにします。

## 2. 書く内容

- 文書は次の構成で書きます。
  - `## 1. 概要`: 何のファイルか、どの画面や機能で扱うかを一文で書きます。形式（JSON、Excel、CSV など）も書きます。
  - `## 2. 構成`: ファイルの全体の形を書きます。JSON の場合は、コードブロックで全体の形を示し、含まれる設定の名前を一文ずつ書きます。Excel の場合は、シートの一覧を表（シート名、役割）で示します。
  - `## 3. 各設定の詳細について`（Excel の場合は `## 3. 各シートの詳細について`）: 設定ごとに `### 設定名` の節を作り、その中に項目の表と注意を書きます。
  - `## 4. 設定ファイルのサンプル`（Excel の場合は `## 4. サンプル`）: 全体の形を示す 1 つの例を書きます。
- 節の最初の文は、その設定がどのキーで指定されるかを書きます（例: 「アプリの設定は`appConfig` で、次の項目を指定します。」）。
- 書く前に、実装（読み書きの処理）を確認し、名前、値の種類、既定値、必須かどうかを、実装と一致させます。

## 3. 項目の表

- 項目の表は 3 列にします。列は「項目名」「内容」「利用できる値」の順にします。
- 項目名は、ファイルに書く名前をバッククォートで囲んで書きます（例: `themeMode`）。
- 利用できる値には、取りうる値と例を書きます（例: `LIGHT` / `DARK`、例）`LIGHT`）。
- 内容は、「〜します。」の形で書きます。
- 表の列幅は、PDF 変換の CSS で指定します。項目名の列は折り返さない設定にし、最も長い項目名が収まる幅にします。
- 形式が Excel の場合は、項目名の代わりに「列名または欄の名前」と書き、シート名と欄の位置（列、セル、範囲）を「内容」に書きます。Excel の入力規則（選べる値、数値の範囲）や、数式で決まる欄は、「利用できる値」に書きます。

## 4. 注意の書き方

- 注意は、節ごとに `> **注意**` の引用で書きます。1 項目 1 文にします。
- 次の内容は、必ず注意に書きます。
  - 省略された項目や、設定ごと省略されたときの扱い（既定値に戻るか、現在の値が残るか）
  - 必須の項目と、ない場合に起きること（エラーになるなど）
  - 重複、順序、既存のデータとの統合（上書きか追加か）の扱い
  - 利用できる値以外が書かれたときの扱い

## 5. サンプル

- サンプルは、ファイルに含まれる設定をすべて含みます。

## 6. 用語

- 名前は、画面に表示される名前と揃えます。
- 「設定内容」とは書かず、表の中身は「項目」と書きます。

## 7. 変更時の確認

- ファイルの形式を変えたら、この仕様書、サンプル、関連する画面設計、テスト仕様書、マニュアルを同じタイミングで更新します。
- 項目名と値を、実装と照合して確認します。
- 変更したら、UTF-8 として正しいか確認します。
