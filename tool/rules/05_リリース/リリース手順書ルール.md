# リリース手順書ルール

対象: `doc\05_リリース\リリース手順書.md`

共通の書き方は「共通ルール」を参照してください。

## 1. 目的

導入する担当者が、配布されたツールを PC に導入し、使える状態にできるようにします。

## 2. 書く内容

- 文書は次の構成で書きます。
  - `## 1. 目的と対象`: 何のツールか、誰が導入するかを書きます。
  - `## 2. 用意するもの`: 導入の前に、担当者が用意するもの（PC 環境、Excel、管理者から渡される情報など）を箇条書きで書きます。
  - `## 3. 導入の手順`: 作業ごとに節に分けます。節の並びと節名は、「5. 書式」に従います。各節の中を、作業の順に番号付きで書きます。番号は節をまたいで続けます。
  - `## 4. 注意事項`: 導入の作業で特に気をつけることだけを書きます。

## 3. 導入の手順の書き方

- 配布の形式、展開後のフォルダ構成は、プロジェクトごとに書きます。フォルダ構成は、「- ツールのフォルダ」の行の下に、コードブロックで書きます。ツールの実行時に作られるフォルダは、構成には含めず、その旨を一文で書きます（例: 「ツールを実行すると、出力先のフォルダとログのフォルダが自動で作られます。」）。
- 1 手順には、目的が 1 つの作業だけを書きます。
- GUI で初期設定を行う場合は、節の見出しの直下に、「この節の詳しい操作は、操作マニュアルの「○○」を参照してください。」と書きます。手順には、画面の名前やボタンの名前を書いても構いません。ただし、操作の詳しい手順（入力する内容や、操作の細かい順番）は書かず、操作マニュアルを参照します。
- 保存などの操作で作られるファイルは、その操作の手順の中で書きます。
- 値（接続情報、ID など）は書きません。「用意するもの」に書いたものを、「用意した値」と書きます。
- bat ファイルを編集する手順は、コードブロックの前に「- ファイル名.bat」の行を書きます。値は書かず、値の部分を（　）で示します。
- Excel の内容を変更する手順は、表の前に「- ファイル名：シート名」の行を書きます。表には、変更するシートの内容を書き、変更する箇所を（　）で示します。
- 導入後の確認は、「導入の確認（GUI）」「導入の確認（バッチ）」の節に書きます。確認で外部のサービス（kintone など）へ投稿される場合は、その旨を手順の中に書きます。
- 導入の確認は、ツールが動いて結果が出たことを確かめる内容にします。結果のファイルは「開く」で開けることを確認し、中身の確認は書きません（中身は受け入れテストで確認済みとします）。

## 4. 注意事項

- 導入の作業で特に気をつけることだけを書きます。
- 接続情報（パスワードを含む）の共有など、導入時に必要な注意を書きます。
- 運用の注意（集計の実行、自動実行の動き、ファイルの扱い）は、操作マニュアルに書き、この手順書には書きません。

## 5. 書式

- 文書の見出しは、`# リリース手順書` とします。
- 章の見出しは `## 1. 目的と対象`、`## 2. 用意するもの`、`## 3. 導入の手順`、`## 4. 注意事項` の 4 つに限り、この名前と番号を変えません。
- 節の見出しは `### ○○` とし、作業の名前で書きます。節の見出しに、番号は付けません。節の並びは、配布物の展開、初期設定、導入の確認（GUI）、自動実行の登録（バッチ）、導入の確認（バッチ）の順にします。外部のサービスへのログインが必要なプロジェクトは、初期設定の後、導入の確認（GUI）の前に「外部環境へのログイン」の節を置きます。自動実行がないプロジェクトは、自動実行の登録（バッチ）の節を書きません。バッチの実行がある場合は、導入の確認（バッチ）の節を書きます。GUI だけのプロジェクトは、バッチの節を書きません。
- 手順は番号付きで書きます。1 手順は、1 文を基本とし、文末は「。」で終わります。
- 手順の補足は、手順の下にインデントした箇条書き（「   - 」）で書きます。手順の中で文が 2 つ以上になるときは、2 文目以降を補足にします。
- 「用意するもの」と「注意事項」は、箇条書き（「- 」）で書きます。1 項目は 1 文にし、文末は「。」で終わります。
- 手順に出てくる名前は、本文の中で同じ書き方にそろえます（例: 「ツールのフォルダ」）。最初に出てきたところで、「展開したフォルダを「ツールのフォルダ」と呼びます。」と定義します。
- ファイル名・フォルダ名は、そのまま書きます（「」で囲みません）。画面の名前、ボタンの名前、タブの名前は、「」で囲みます。
- 手順の中で、ほかの手順を参照するときは、「手順 N」と書きます。
- コードブロックは、フォルダ構成（言語の指定なし）と、bat の内容（`bat` と指定）に使います。

## 6. 更新

- 配布物（実行ファイル、bat、フォルダ構成）を変えたときは、同じときにリリース手順書も直します。
- 画面の名前やボタンの名前が変わったときは、リリース手順書も直します。操作の詳細だけが変わったときは、操作マニュアルだけを直します。
