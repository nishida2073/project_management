# データ設計ルール

対象: `kintone-aggregator\doc\02_設計\データ設計.md`

共通の書き方は「共通ルール」、設計全体の書き方は「設計ルール」を参照してください。

## 1. 目的

利用者が環境設定で変更するファイルで扱う項目を定義します。

対象の判定は次の基準で行います。

- 環境設定の画面で保存されるファイル、または利用者が変更するファイルは対象にします。
- 処理の中で読むだけの固定の列対応、処理の結果として出力されるファイル（集計データ、アラート結果、テンプレートなど）は対象外にします。

対象のファイルはプロジェクトごとに異なります。対象は、そのプロジェクトのコードで判定して書きます。

次は kintone-aggregator の対象です。

- 共通設定: `bats\common.bat`
- グループ別の設定: `clients\<グループ名>.bat`（雛形: `clients\template\client.bat`）
- グループ別のデータ: `clients\<グループ名>.xlsx`（雛形: `clients\template\client.xlsx`）
- 集計データの列定義: `bats\collect-data-defs.json`

対象外は次のファイルです。

- 同期の列対応: `bats\sync-kintone-to-sheet.json`（画面で編集しない固定の対応）
- アラート結果のテンプレート: `template\アラート検知.xlsx`

## 2. 書く内容

- 文書は次の構成で書きます。
  - `## 1. 概要`: 文書の対象を 1 段落で書きます。
    - `### 1.1 データの一覧`: データの種類を表で書きます（データ、保存先（ファイル）、概要）。概要は、データの役割を 1 文で書き、文末を「設定する」にそろえます。単位や件数は書きません。
  - `## 2. 各データ`: 各データの項目を書きます。
    - `### 2.1 共通設定`、`### 2.2 グループ別の設定`、`### 2.3 受講生一覧`、`### 2.4 スケジュール` のように、データごとに節を分けます。
  - `## 3. 注意事項`: 業務上の不都合になる内容だけを、箇条書きで書きます。
- 各データの項目は表で書きます。設定値の項目は、項目、変数、内容、既定値の列で書きます。
- 項目の名前は、環境設定の画面（共通、グループ別、マスターの各タブ）の表示文言に合わせます。環境変数名は「変数」の列にだけ書きます。
- 内容の列は、先頭に項目名を置かず、説明の一文で書きます（例: 「kintone の接続に使うログイン名です。」）。
- 雛形の既定値は、雛形のファイルの値と一致させます。
- 確認していない内容は「（未確認）」と明記します。

## 3. 例外

- 「データの一覧」の節と、各データの「変数」の列では、実ファイル名と環境変数名を書いてかまいません。
- 「各データ」の本文では、実ファイル名を書いてかまいません。ただし、関数名や引数名は書きません。

## 4. 注意

- 設定値の既定値の一覧は、データ設計にだけ書きます。他の設計文書では、場所と役割だけを書きます。
- 機密情報（パスワードなど）の保存場所は書きますが、値は書きません。
