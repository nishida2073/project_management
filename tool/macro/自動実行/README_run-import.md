# run-import

`計画算定シート`の「実績反映」（`ImportFromOtherBook`マクロ）を、ファイル選択ダイアログを使わずバッチから実行するツールです。実績データのExcelファイルを、指定したフォルダから自動で見つけて使います。

このフォルダ（`自動実行`）は、対象の`原価管理シート.xlsm`が置かれている`macro`フォルダの**1つ下の階層**にあります。

## 構成

- `run-import.bat` — 実行用のラッパー（中身は英数字のみ）
- `run-import.ps1` — 実際の処理を行うPowerShellスクリプト
- `run-import-task.xml` — Windowsタスクスケジューラにインポートするためのタスク定義（下記「定期実行の設定」を参照）
- `実績データ/` — 実績データの`.xlsx`を置くサブフォルダ（`run-import.bat`は既定でここを`-DataDir`として渡します）
- `logs/` — 実行ログを日付ごとに出力するサブフォルダ（`run-import.bat`は既定でここを`-LogDir`として渡します）
- `backup/` — 実行のたびに作られる、対象`.xlsm`のバックアップを置くサブフォルダ（`run-import.bat`は既定でここを`-BackupDir`として渡します）

## 基本的な使い方

### 手順

```bat
run-import.bat
```

- `-DataDir`：実績データの`.xlsx`が入っているフォルダ。`run-import.bat`は既定で自分のフォルダ内の`実績データ`サブフォルダを渡します
- `-XlsmPath`：対象の`.xlsm`ファイルへの直接パス。`run-import.bat`は既定で、1つ上の`macro`フォルダにある`原価管理シート.xlsm`を渡します（省略した場合は`run-import.ps1`と同じフォルダから、`.xlsm`が1つだけある前提で自動検出します）
- `-LogDir`：ログの出力先フォルダ。`run-import.bat`は既定で自分のフォルダ内の`logs`サブフォルダを渡します。フォルダが無ければ自動的に作成されます
- `-BackupDir`：バックアップの出力先フォルダ。`run-import.bat`は既定で自分のフォルダ内の`backup`サブフォルダを渡します。フォルダが無ければ自動的に作成されます

```bat
run-import.bat -XlsmPath "C:\path\to\別の原価管理シート.xlsm"
```

※`run-import.bat`は既定で`-DataDir`・`-LogDir`・`-BackupDir`・`-XlsmPath`をすべて固定して渡すため、`.bat`経由でこれらをさらに指定するとエラーになります。変えたい場合は`run-import.ps1`を直接呼び出してください。

### 処理内容

1. `-XlsmPath`（省略時は自動検出）で対象の`.xlsm`を特定する
2. `-DataDir`内の`.xlsx`をすべて洗い出し、**更新日時が古い順**に並べる
3. `-DataDir`に`.xlsx`が1つも無ければエラーで終了
4. 対象の`.xlsm`を、`-BackupDir`にタイムスタンプ付きのファイル名（例：`原価管理シート_20260911-143000.xlsm`）でコピーする（自動削除はしないため、実行するたびに増えていきます）
5. 対象の`.xlsm`をExcelで（非表示で）開く
6. 並べた順（古い→新しい）に、それぞれの`.xlsx`について`ImportFromOtherBook`マクロをファイルパス付きで実行（ファイル選択ダイアログは出ません）。同じ計画算定シートの行に複数のファイルがマッチした場合、**最後に処理される＝一番新しいファイルの値**が最終的に残ります
7. すべて処理し終えたら`HandleBeforeSave`（黒字化処理）を呼んでから上書き保存して閉じる
8. 各ファイルの結果（反映件数・スキップ件数の内訳、またはエラー内容）、バックアップ先、最終的な保存結果を、`-LogDir`内の`run-import_YYYY-MM-DD.log`とコンソールに出力

`ImportFromOtherBook`は、引数を渡さずに呼ばれた場合（ボタンから手動実行した場合）は今まで通りファイル選択ダイアログと結果の`MsgBox`を出しますが、引数（ファイルパス）を渡して呼ばれた場合は`MsgBox`を一切出さず、結果を文字列の戻り値として返すようになっています。バッチ実行中に非表示のExcelでダイアログが出て止まってしまう、という事態を避けるためです。

保存前の黒字化処理（`HandleBeforeSave`）も、`Application.EnableEvents`をONにしてイベント発火に任せるのではなく、`Application.Run`で直接呼び出しています。

### 注意点

- 対象の`.xlsm`を上書き保存する、後戻りしにくい操作です。実行前に`backup`フォルダへ自動でコピーが作られますが、古いバックアップの削除は行われないため、定期的に手動整理してください
- 対象の`.xlsm`をExcelで開いている場合は閉じてから実行してください

## 定期実行の設定（タスクスケジューラ）

`run-import-task.xml` をWindowsのタスクスケジューラにインポートすると、`run-import.bat`を定期実行するタスクを作成できます。

`run-import-task.xml`内の`<Actions><Exec><Command>`と`<WorkingDirectory>`は、`C:\myrepo\project_management\tool\macro\自動実行\...`という絶対パスで固定されています。リポジトリを別の場所や別のPCに置く場合は、インポート前にこのXML内のパスを実際の場所に書き換えるか、インポート後にタスクスケジューラの「操作」タブから編集してください。

### 手順

1. `Win + R` → `taskschd.msc` でタスクスケジューラを開く
2. 右側の「操作」ペインから「**タスクのインポート...**」を選び、`run-import-task.xml`を選択
3. 「タスクの作成」画面が開くので、「名前(M):」欄に好きな名前（例：`実績反映バッチ`）を入力してから「OK」

   - この画面の「名前」欄は既定でファイル名（`run-import-task`）が入りますが、そのまま上書きして構いません
   - 既定では「ユーザーがログオンしているときのみ実行する」になっています。Excelの自動化はサインインしたデスクトップセッションを前提にしているため、基本的にこの設定のまま使ってください

4. インポート後、「トリガー」タブから実行時刻・頻度を編集できます（既定では毎日12:00）
5. 一度手動で「実行」し、`logs\run-import_YYYY-MM-DD.log`にログが出るか、`backup`フォルダにバックアップが作られるかを確認してください

## SharePointを使った同期

この`自動実行`フォルダは、SharePoint上のドキュメントライブラリと同期されているフォルダとして扱います。他のメンバーがSharePoint側に実績データをアップロードすると、同期によってこのフォルダ内（`実績データ`サブフォルダ）に自動的にファイルが降ってくる、という運用を想定しています。

フォルダ構成は次の通りです（`原価管理シート.xlsm`も同じ同期フォルダの中に置きます）。

```
自動実行/                        ← このフォルダ全体がSharePointと同期される
├─ 原価管理シート.xlsm
├─ run-import.bat
├─ run-import.ps1
├─ run-import-task.xml
├─ 実績データ/
├─ logs/
├─ backup/
└─ README_run-import.md
```

※このリポジトリ上の現在の配置では`原価管理シート.xlsm`が`自動実行`の1つ上の`macro`フォルダにありますが、実際にSharePoint同期フォルダとして運用する際は、`run-import.bat`内の`-XlsmPath`を、1つ上の階層（`..\`）ではなく同じフォルダを指すように書き換えてください。

### 手順

1. ブラウザでSharePointサイトの対象ドキュメントライブラリを開き、コマンドバーの「**同期**」をクリック（見当たらない場合は「...」の中、または権限不足の可能性があります）
2. 初回はOneDriveアプリへのサインインを求められるので、そのSharePointサイトへのアクセス権を持つ**組織アカウント**でサインインする
3. 同期が完了すると、通常 `C:\Users\<ユーザー名>\<組織名>\<サイト名> - <ライブラリ名>\` にローカルフォルダが作成される
4. そのフォルダの中身を`自動実行`フォルダの構成に合わせて配置する（または、そのフォルダ自体を`自動実行`として扱い、タスクスケジューラや`run-import.bat`のパスをそちらに向ける）

### 注意点

- 同期には、そのSharePointサイト（ライブラリ）に対する**「編集」以上の権限**が必要です。権限が無いと同期ボタンが出ない、または同期時に「アクセス権がありません」というエラーになります
- 組織によっては、会社管理下のデバイスからしか同期できない（Conditional Access）等の制限がある場合があります。うまく同期できない場合はIT部門に確認してください
- **`原価管理シート.xlsm`自体を同期対象に含める場合、`run-import.bat`がExcelでファイルを開いている最中にOneDriveがクラウド側との同期を試みると、競合（他のバージョンとの重複ファイル作成など）が起きる可能性があります。** 心配な場合は、同期対象を`実績データ`フォルダだけに絞り、`原価管理シート.xlsm`自体はローカルの`macro`フォルダに置いたままにする運用の方が安全です
- タスクスケジューラの実行によって更新された`原価管理シート.xlsm`は、OneDriveの双方向同期により**自動的にSharePoint側にもアップロードされます**。ただし、Excelがファイルを開いている間（`run-import.ps1`の処理中）はOneDriveがロック中とみなしてアップロードを待機するため、実際にアップロードされるのは保存・クローズが完了した**後**になります
- 同じタイミングでSharePoint側から直接そのファイルが編集されていた場合は、OneDriveが競合を検知し、「競合バージョン」という別名の重複ファイルが作られることがあります
