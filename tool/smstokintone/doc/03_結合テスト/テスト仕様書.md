# テスト仕様書

## 1. 概要

本ツールの画面を操作して、画面ごとの動作を確認します。利用者の操作から、画面の表示、作られる設定ファイル、kintone への登録などの結果までを確認します。SMS を受信したときの自動処理も確認します。

- 前提条件
  - テスト用の kintone アプリを使います。業務で使うアプリには接続しません。
  - テスト用の kintone アプリには、送信先の設定で使うフィールド（登録種別、受信日時、送信元、履歴）が作られているものとします。
  - テスト用の kintone 接続情報（接続先、ログイン名、パスワード、アプリID）を使います。実際の値は書きません。
  - SMS は、テスト端末とは別の端末（もう 1 台）から送って受信します。
  - テスト端末: Android 端末（機種、Android のバージョン: （未確認））
  - AI 抽出のテストには、Gemini Nano に対応した端末を使います。対応端末の機種: （未確認）
  - SMS の読み取り、受信、送信の権限は、ケースに応じて許可した状態と許可しない状態を用意します。

- テスト送信（2.2 の 8、9）と SMS の受信による登録（2.8）は、テスト用の kintone アプリに実際に登録されます。同じ送信元の既存のレコードがあると、新規登録ではなく追記（更新）になることがあります。
- SMS受信の自動処理は、別の端末から SMS を送って確認します。テスト端末とは別に、もう 1 台の端末を用意します。
- AIによる抽出（2.8 の 4）は、Gemini Nano に対応した端末でだけ確認できます。対応していない端末では、2.8 の 5 の結果（ルールに基づく抽出）を確認します。
- 実行は番号順に行います。次の前の結果を使うケースは、次のとおりです。
  - 2.2 は、2.2 の 1 から 9 で追加した送信先を、2.2 の 10 の保存の前に削除します（一覧を テスト送信先1 と テスト送信先2 の状態に戻します）。2.2 の 11 以降は、2.2 の 10 の保存後の状態から実行します。
  - 2.2 の 3 は、2.2 の 1 で追加した空の送信先を使います。
  - 2.4 の 1 から 12 は、2.8 の 1 の SMS 受信で作られた引継ぎ内容を使います。2.4 の 10 は、画面を開いた後で 2.8 の 1 を実行します。
  - 2.6 のログの確認は、2.8 の自動処理を先に実行して作ったログを使います。
  - 2.7 の検索は、2.8 の自動処理で登録済みの SMS（送信済み）を含む状態で実施します。2.7 の 11 は、2.7 の 9 で送信した SMS を再度送信します。
  - 2.8 の 2 と 2.8 の 3 は、2.8 の 1 の登録の後で実行します。
  - 2.8 の 14 は、2.8 の 13 の直後に実行します。
- 2.6 のログの確認は、受信完了、送信開始、送信完了、返信完了のログをそれぞれ準備します（2.8 のケースで作成します）。
- ログの削除（2.6 の 2）は取り消せません。テスト用の端末で実施します。
- 設定のエクスポート（2.5 の 2）で作られたファイルには、送信先のログイン名とパスワードが平文で含まれます。テストで作ったファイルは、テスト後に削除します。テスト用の値以外は、実際の値を入れません。
- 2.7 の 15（読み取りの失敗）と 2.5 の 16（書き出しの失敗）は、再現の方法が未確認です。再現の方法が分かったら、入力値に書きます。
- テスト送信のログは、ログの画面には残りません。
- 実施結果の欄は、テストを実施したときに記入します。
