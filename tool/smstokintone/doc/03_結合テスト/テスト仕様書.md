# テスト仕様書

## 1. 概要

本ツールの画面を操作して、画面ごとの動作を確認します。利用者の操作から、画面の表示、作られる設定ファイル、kintone への登録などの結果までを確認します。SMS を受信したときの自動処理も確認します。

- 前提条件
  - テスト用の kintone アプリを使います。業務で使うアプリには接続しません。
  - テスト用の kintone アプリには、送信先の設定で使うフィールド（登録種別、受信日時、送信元、履歴）が作られているものとします。
  - テスト用の kintone 接続情報（接続先、ログイン名、パスワード、アプリID）を使います。実際の値は書きません。
  - SMS は、テストデータ（test-data\sms\<フロー名>.json）の内容を、テストの実行の中で受信させます。
  - テスト端末: Android 端末（機種、Android のバージョン: （未確認））
  - AI 抽出のテストには、Gemini Nano に対応した端末を使います。対応端末の機種: （未確認）
  - SMS の読み取り、受信、送信の権限は、ケースに応じて許可した状態と許可しない状態を用意します。

### 2.8 自動処理（SMS受信の自動処理・SMS送信の自動処理）

- 前提条件
  - 各行は、test-data\setup\env_base.json を読み込んだ直後の状態を前提にします。送信先の設定には、test-send-target-1（振り分け：test-company）の 1 件が保存されています。接続情報は JSON の値です（値は書きません）。
  - 引継ぎ内容には、JSON の 2 件（送信元：test-sender-a、test-sender-b）が保存されています。
  - アプリの設定は既定値（SMSの送信モード：自動、SMSの返信モード：手動、会社名の抽出：あり）とします。ケースごとに変える項目は入力値に書きます。
  - SMSの読み取り、受信、送信の権限は許可しておきます（2.8 の 22、23 を除く）。
  - 操作の「別端末から SMS を受信します。」は、テストデータの SMS を送って受信することを指します。
  - 送信先はデフォルトの送信先を持たないため、会社名が振り分けに一致しない SMS（会社名の抽出が異常な SMS を含む）は、送信開始のログ（失敗：SMSの送信先が存在しません）だけが残ります。2.8 の 12 と 16 は、この前提で送信開始のログ（失敗）を期待値にします。2.8 の 17 は会社名の抽出が無効のため、送信先はすべての送信先（この JSON では 1 件）になり、送信完了のログを期待値にします。
  - 同じ送信元の 2 通目以降は、1 通目の引継ぎ内容で振り分けます。各行の前提の操作で、必要な 1 通目を受信します。

## 3. 注意事項

- テスト送信と SMS の受信による登録は、テスト用の kintone アプリに実際に登録されます。同じ送信元の既存のレコードがあると、新規登録ではなく追記（更新）になることがあります。
- SMS受信の自動処理は、テストデータの SMS を送って確認します。テスト端末とは別に、もう 1 台の端末を用意します。
- 各行は、前の行の結果を使いません。実行の順番は問いません。必要な状態は、その行の中で作ります（行をまたいだ引き継ぎはありません）。
- テストで使うログ（受信完了、送信開始、送信完了、返信完了）は、各行の前提の操作で作るか、外部条件としてテストデータの SMS を受信して作ります。
- 実施結果の欄は、テストを実施したときに記入します。
